# 맨홀 경고 진동 키링

침수 위험 맨홀 근처에서 진동하는 키링. 폰과 블루투스로 붙어 있다.

**판단은 폰이 하고, 키링은 진동만 한다.** 키링에는 GPS 도 지도도 없다.

```
[폰]  GPS 로 내 위치 확인
      → 반경 15m 안에 위험 맨홀이 있나
      → 그 맨홀이 지금 특보에서 위험한가
      → 최근 60초 안에 같은 맨홀로 울린 적 없나
      ↓  다 맞으면 1 바이트 전송
[키링] 진동
```

비 오는 날 우산을 들고 걸으면 주머니 속 폰 진동을 못 느낀다. 가방이나 손목에
달린 키링은 느낄 수 있다. 그게 이 물건이 있는 이유다.

---

## 부품

| 부품 | 규격 | 대략 |
|---|---|---|
| Seeed XIAO nRF52840 | 21×17.5mm · BLE 5.0 · USB-C 충전회로 내장 | 1만원 |
| 코인 진동모터 | ERM 10mm × 3mm · 3V · 약 80mA | 2천원 |
| N채널 MOSFET | 2N7002 또는 AO3400 | 5백원 |
| **플라이백 다이오드** | 1N4148 | 2백원 |
| 저항 | 10kΩ | 백원 |
| LiPo 배터리 | 3.7V 100mAh · **보호회로 포함** | 5천원 |
| 케이스 | 3D 프린팅 · 약 30×25×12mm | — |

**합계 약 2만원 / 개.** 납땜 지점은 4곳뿐이다.

### 왜 XIAO 인가

칩만 사면 못 쓴다. nRF52840 칩은 6×6mm 에 다리가 73개, 간격 0.5mm 라 인두로는
손도 못 댄다. 게다가 칩 혼자서는 안 돌아간다 — 32MHz 크리스털, 안테나와 매칭
회로, 전원 레귤레이터, 커패시터 수십 개가 있어야 한다.

XIAO 는 그걸 다 붙여놓은 21×17.5mm 모듈이다. 500원 동전만 하다.

**충전회로(BQ25101)가 들어 있는 게 크다.** 배터리를 바로 연결하고 USB-C 를 꽂으면
알아서 충전된다. 딥슬립 전류가 5μA 라 가만히 있을 때는 전기를 거의 안 먹는다.

> 아두이노 회사 제품이 아니다. 코드 짜는 방식만 아두이노를 빌려 쓴다.

## 배선

```
              ┌─────────────────┐
              │  XIAO nRF52840  │
              │                 │
              │  D0 ────────────┼──┬─────────── MOSFET 게이트
              │                 │  │
              │                 │  └── 10kΩ ──┐
              │  GND ───────────┼─────────────┴── MOSFET 소스
              │                 │
              │  BAT+ ──────────┼──┐
              │  BAT- ──────────┼──┼── 배터리 −
              └─────────────────┘  │
                                   │  배터리 +
                                   ├──────────┬─────────────┐
                                   │          │             │
                                   │        진동모터 +   다이오드 캐소드(줄무늬)
                                   │          │             │
                                   │        진동모터 −      │
                                   │          │             │
                                   │          ├─────────────┘
                                   │          │        다이오드 애노드
                                   │     MOSFET 드레인
                                   │          │
                                   └──────────┴── (소스는 GND)
```

정리하면 이렇다.

```
D0 ──── MOSFET 게이트          10kΩ 로 GND 에도 연결 (풀다운)
배터리+ ─ 모터 ─ MOSFET 드레인 ─ GND
다이오드는 모터와 병렬. 줄무늬 쪽이 배터리+ 방향
```

### 모터를 D0 에 직접 물리면 안 된다

모터가 **80mA** 를 먹는데 GPIO 핀은 **15mA** 까지다. 직접 연결하면 핀이 탄다.
MOSFET 이 스위치 역할을 한다 — 작은 신호로 큰 전류를 여닫는 부품이다.

### 플라이백 다이오드를 빼먹으면 안 된다

모터는 안에 코일이 감겨 있다. **코일은 전원을 끊는 순간 반대 방향으로 고전압을
튕겨낸다.** 수십 V 가 순간적으로 튀는데, 이게 갈 데가 없으면 MOSFET 과 MCU 를
때린다.

다이오드가 그 전기를 모터 안에서 뱅뱅 돌게 만들어 열로 태워버린다.

> **처음엔 멀쩡하다.** 몇십 번, 몇백 번은 잘 된다. 그러다 어느 날 죽고,
> 그때 가서는 왜 죽었는지 못 찾는다. 초보가 제일 많이 빠뜨리는 부품이다.

### 10kΩ 풀다운은 왜

전원을 켜는 순간 MCU 핀은 잠깐 붕 뜬 상태가 된다. 그 사이 게이트 전압이
어중간하면 모터가 제멋대로 떤다. 저항이 게이트를 GND 로 붙잡아 둔다.

## 굽는 법

### 1. Arduino IDE 에 보드 추가

```
파일 → 환경설정 → 추가 보드 매니저 URL 에 붙여넣기
https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json

도구 → 보드 → 보드 매니저 → "Seeed nRF52" 검색 → 설치
도구 → 보드 → Seeed nRF52 Boards → Seeed XIAO nRF52840
```

### 2. 라이브러리

보드 패키지에 `Adafruit Bluefruit nRF52` 가 같이 들어온다. 따로 설치할 게 없다.

### 3. 업로드

USB-C 로 연결하고 포트를 고른 뒤 업로드. 포트가 안 보이면 **리셋 버튼을 빠르게
두 번** 눌러 부트로더 모드로 들어간다. 초록 LED 가 천천히 깜빡이면 준비된 것이다.

## 검증 — 순서대로

한 번에 다 만들면 안 될 때 원인이 어디인지 못 가린다. **앞 단계가 되는 걸 확인하고
다음으로 간다.**

### 1단계 · 하드웨어만 (앱 없이)

폰에 **nRF Connect** (Nordic 제작, 무료) 를 깔고:

```
스캔 → "ManholeKeyring" 연결
→ 커스텀 서비스 열기 → characteristic 의 ↑ (write) 누르기
→ 값에 01 입력 (Byte Array) → Send
```

**진동하면 회로와 펌웨어는 끝난 것이다.** 여기까지 되면 남은 건 전부 앱 문제다.

| 넣는 값 | 결과 |
|---|---|
| `01` | 짧게 한 번 (0.2초) |
| `02` | 길게 한 번 (0.6초) |
| `03` | 세 번 — 시연 때 쓸 것 |
| `00` | 정지 |

연결하는 순간에도 짧게 한 번 떤다. 주머니 안에서도 붙은 걸 알 수 있다.

### 2단계 · 앱 연동

앱의 테스트 버튼으로 `03` 을 보내 진동하면 BLE 연결 완성.

### 3단계 · 판정 로직

앱 개발자 화면에서 **판정 반경을 500m 로 키우고** 밖에서 걸어본다. 아무 데서나
울리면 위치 판정이 도는 것이다. 확인했으면 15m 로 되돌린다.

### 4단계 · 실제 조건

반경 15m, 특보 수동으로 `100`. 침수 구간 맨홀 옆을 지나가면 울린다.

### 5단계 · 배터리

완충 후 하루 방치하고 잔량을 본다. 딥슬립 5μA + BLE 연결 유지면 100mAh 로
며칠은 가야 정상이다.

## 앱이 지켜야 할 것 (D 에게)

### BLE

```
기기 이름     ManholeKeyring
서비스 UUID   6e400001-b5a3-f393-e0a9-e50e24dcca9e
쓰기 UUID     6e400002-b5a3-f393-e0a9-e50e24dcca9e
값            1 바이트 (위 명령표)
```

Flutter 는 `flutter_blue_plus` + `geolocator`.

### 경고 판정

서버에서 `GET /v1/warning-manholes` 로 목록을 받아 **폰에 저장한다.**
5,975개 · 140KB. 매번 서버에 묻지 않는다 — 비 오는 날 골목에서 신호가 약해지면
그때 경고가 멈추면 안 된다.

```dart
// 1초마다. 5,975개를 그냥 순회한다.
// ponytail: 공간 인덱스 없음. 위경도 델타로 먼저 거르면 실제 거리 계산은 몇 개뿐이다.
//           맨홀이 몇 만 개로 늘면 그때 격자 버킷을 넣는다.
for (final m in warningManholes) {
  if ((m.lat - here.lat).abs() > 0.00015) continue;   // 약 17m. 싼 검사 먼저
  if ((m.lon - here.lon).abs() > 0.00019) continue;
  if (m.minFreq > currentAlert) continue;             // 특보가 약하면 무시
  if (distanceM(m, here) > 15) continue;
  if (recentlyBuzzed(m.id)) continue;                 // 60초 쿨다운
  keyring.write([0x01]);
  markBuzzed(m.id);
}
```

**쿨다운이 없으면** 맨홀 하나 옆에 서 있는 동안 1초마다 울린다.

**반경 15m 를 더 줄이면 안 된다.** GPS 오차가 3~10m 라 그보다 좁게 잡으면
바로 옆을 지나가도 못 잡는다.

### 특보 값

| 특보 | 값 | 이때 경고하는 맨홀 |
|---|---|---|
| 평상시 | 0 | 없음 — 뚜껑이 보이니 사람이 피한다 |
| 호우주의보 | 50 | `min_freq <= 50` → 3,867개 |
| 호우경보 | 100 | + 1,901개 |
| 극한호우 | 9999 | + 207개 |

### 백그라운드

안드로이드 기준이다. **포그라운드 서비스 + 상단 알림**을 유지해야 화면을 꺼도
위치 감시와 BLE 연결이 살아 있다. 아이폰은 Core Bluetooth 백그라운드 제약이
심하고 실기기 테스트에 개발자 등록이 필요해 별도 항목으로 뺀다.

## 시연 준비 — 이게 없으면 발표가 망한다

채택한 조건(침수 구간 + 특보)은 **맑은 날 아예 안 울리고, 비가 와도 15분에 한 번**
꼴이다. 3분 시연 동안 한 번도 안 걸릴 확률이 높다.

| 장치 | 하는 일 |
|---|---|
| 특보 수동 지정 | 앱에서 평상시/주의보/경보/극한호우를 손으로 고른다 |
| 진동 테스트 버튼 | `03` 을 보내 연결 상태를 즉석에서 보여준다 |
| 판정 반경 조절 | 15m → 100m. 시연장 근처 맨홀을 억지로 걸리게 한다 |

**임시방편이 아니라 정식 기능이다.** 날씨와 무관하게 "호우경보라면 어떻게 되는지"를
보여줄 수 있어야 한다.

## 잘 안 될 때

| 증상 | 볼 것 |
|---|---|
| 포트가 안 보임 | 리셋 버튼 빠르게 두 번 → 초록 LED 깜빡임 확인 |
| 스캔에 안 잡힘 | 폰 블루투스 껐다 켜기. 다른 폰에 이미 연결돼 있으면 안 보인다 |
| 연결은 되는데 진동 안 함 | UUID 가 앱과 펌웨어에서 같은지. 하나만 달라도 조용히 실패한다 |
| 계속 떨림 | 10kΩ 풀다운이 빠졌거나 MOSFET 방향이 뒤집혔다 |
| 며칠 쓰다 죽음 | **플라이백 다이오드를 확인한다.** 십중팔구 이것이다 |
| 배터리가 하루도 못 감 | `sd_app_evt_wait()` 가 `loop()` 에 있는지. 없으면 계속 깨어 있다 |
